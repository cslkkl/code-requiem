# 决策：忽略 ruff UP031（% 格式化）(2026-11-05)

状态：生效

## 问题

`src/narrative.py` 与 `src/prompts.py` 里有 90 处用 `%` 拼接中文 Markdown 模板
（如 `"生于 %s" % _short_date(...)`）。ruff 的 `UP031` 规则要求改成 `f-string` 或 `.format()`。

## 决策

`pyproject.toml` 的 `[tool.ruff.lint] ignore` 加入 `"UP031"`，保留 `%` 格式化。

## 替代方案（强制）

- **全量改 f-string**：中文模板里大量 `%s` 与 `{}` 混排会降低可读性；90 处改写
  在一个没写完的项目里是纯风险（且 `%` 与 f-string 在 Markdown 空白字符上行为一致，
  改写不产生任何用户可见收益）。健康分验收依赖这些模板的字节级稳定，改错一个字就掉分。
- **改 `.format()`**：同 f-string，且 `.format` 对 `%` 字面量的转义更啰嗦。
- **关闭 ruff 的 UP 组**：会同时丢掉 `UP` 里真正有用的规则（如 `UP` 系列未使用导入）。

## 影响

- 新增代码如果写 `%` 格式化不会被拦截 —— 这是有意识的取舍，不是遗漏。
- 生成层模板的改动必须跑 `scripts/test_three_modes.py` 验证三种模式的 Markdown 结构完整。
