# 演示视频分镜脚本 — 60–90 秒

> 目标：一个没听过这个项目的人，90 秒内记住三件事——
> **① 输入一个地址就出分数 ② 分数是确定的、能写进报告 ③ bus factor 才是真痛点。**
>
> 与 [`docs/DEVPOST.md`](DEVPOST.md) 第 ⑤ 项逐秒对齐，改任何一边都要同步另一边。

---

## 0. 录制前必做（不做这段，视频一定废）

| # | 动作 | 为什么 |
|---|---|---|
| 1 | **先冷启动一次 Space**，等页面完全加载后再开始录 | HF Spaces 免费档冷启动 30–60 秒，录进去就是一段黑屏转圈，展示分直接掉 |
| 2 | **预跑三个仓库各一次** | 确认分数落在预期区间；如果实测偏离，改脚本里的口播数字，不要 P 图 |
| 3 | 浏览器开无痕窗口，关掉书签栏、扩展图标、其他标签 | 画面干净度 = 展示分 |
| 4 | 浏览器缩放设 **110%–125%**，窗口宽 1600px 左右 | 1080p 下代码和分数都看得清 |
| 5 | 关闭系统通知、微信、邮件弹窗 | 一个弹窗毁一条 |
| 6 | 网络确认通畅（GitHub + PyPI 都要能访问） | 依赖 API 超时会走 8 分中性分，分数和预期不一致 |
| 7 | 准备好旁白稿，先读两遍掐时间 | 中文旁白 90 秒约 280–320 字，超了就是念太快 |

**总时长硬约束：60–90 秒。** 超过 90 秒按规则是减分项，不是"多一点更好"。

## 1. 逐秒时间轴

| 时间 | 镜头 | 画面内容 | 时长 |
|---|---|---|---|
| **0–10s** | 开场钩子 | 静态标题页或 VS Code 里一个陌生仓库的目录树，缓慢推近 | 10s |
| **10–30s** | 活跃仓库 | 贴 `kornia/kornia` → 点击分析 → 等结果 → 总分与六维分数出现 → 滚动到「谁在养我」 | 20s |
| **30–55s** | 死仓库 | 贴归档仓库 → 分析 → 总分极低 → 出现「悼词」→ 滚动到「死因」三行 | 25s |
| **55–75s** | bus factor 价值 | 切回两个结果页的 bus factor 数字对比 → 高亮那一句「这个人离开，项目即终止」 | 20s |
| **75–90s** | 收尾 | 项目 logo / README 顶部 / 访问地址字幕 | 15s |

**合计 90 秒。** 若需压到 60–75 秒，优先砍 0–10s（压成 5s）和 55–75s（压成 12s），**不要砍 30–55s 的悼词段落**——那是创意分的来源。

## 2. 分镜详解（含中英双语旁白）

> 旁白格式：**中文**（主字幕，烧进画面第一行）／*English*（次字幕，第二行，字号 70%）。
> 字幕全部硬编码，不依赖平台 CC，因为评审可能静音观看。

---

### 镜头 1 ｜ 0:00 – 0:10 ｜ 开场钩子

**画面**

- 0:00 黑底白字，两行大字居中（可用 Streamlit 页面顶部充当背景，不要另做花哨动画）：
  - 上行：`你的前任离职了。`
  - 下行：`README 停在两年前。`
- 0:05 画面切到一个陌生仓库的文件树，鼠标缓慢向下滚动（不点任何文件）
- 0:08 出现一行小字：`你到底接手了什么？`

**旁白（中文）**

> 你的前任离职了，README 停在两年前。
> 你接手了这个仓库，但没人告诉你：哪块能动，哪块一动就炸。

**旁白（English subtitle）**

> Your predecessor left. The README stopped two years ago.
> You inherited this repo — and nobody told you which file is load-bearing.

**要点**：这 10 秒不出现产品名。先制造问题，再给方案。

---

### 镜头 2 ｜ 0:10 – 0:30 ｜ 贴活跃仓库，出遗嘱

**画面**

| 秒 | 动作 |
|---|---|
| 0:10 | 切到 Code Requiem 界面（已预热，无 loading） |
| 0:12 | 输入框粘贴 `https://github.com/kornia/kornia`，鼠标可见地点击「分析」 |
| 0:14 | **不剪辑**，保留进度条 / 转圈（这是实现分的证据） |
| 0:18 | 总分出现：大号数字 + 「存活」徽标 + 绿色 |
| 0:21 | 六维分数条依次展开（最后提交 / bus factor / 趋势 / 依赖 / issue / 文档） |
| 0:25 | 向下滚动到「谁在养我」，展示贡献者占比 |
| 0:28 | 再滚一点，露出「雷区：千万别动」的文件路径列表 |

**旁白（中文）**

> 贴一个仓库地址，它就给你打分。
> 这是 kornia，一个还在活跃维护的库——**八十几分，活着**。
> 六个维度全部拆开给你看，最后提交多久、谁在维护、依赖老不老。
> 再往下，是「雷区」：这几个文件长期没人动，动之前先想清楚。

**旁白（English subtitle）**

> Paste a repo URL. It scores it.
> This is kornia, still actively maintained — **in the eighties, alive**.
> Six dimensions, fully broken down: recency, maintainers, dependency age.
> Scroll down and you get the minefield: files nobody has touched in years.

**口播数字校准**：说"八十几分"而不是精确数字，实测后如落在 75–90 区间均可。若实测 ≥ 90，改说"九十分上下"。

---

### 镜头 3 ｜ 0:30 – 0:55 ｜ 贴死仓库，出悼词

**画面**

| 秒 | 动作 |
|---|---|
| 0:30 | 鼠标点侧边栏「示例仓库」或清空输入框 |
| 0:32 | 粘贴归档仓库地址，点击分析 |
| 0:34 | 同样保留等待过程（这段比上一段久是正常的，不要剪） |
| 0:39 | 总分出现：**低分 + 红色 + 「已故」** |
| 0:42 | 页面标题变成「悼词 · xxx」，出现「生于 / 卒于 / 享年」三行 |
| 0:47 | 滚到「二、死因」，依次高亮：直接原因 / 根本原因 / 加速因素 |
| 0:52 | 停在「根本原因」那一行，画面稍微停顿 1 秒 |

**旁白（中文）**

> 换一个已经死掉的仓库。
> **十几分，已故。**
> 它不再给你遗嘱，它给你一份悼词——
> 生于哪一天，卒于哪一天，享年多久。
> 然后是死因：直接原因是最后一次提交停在了哪，根本原因是——
> 从头到尾，只有一个维护者。

**旁白（English subtitle）**

> Now a repository that's already dead.
> **Barely double digits. Deceased.**
> No will — a eulogy. Born, died, how long it lived.
> Then the cause of death: the last commit, and the root cause —
> from day one, there was exactly one maintainer.

---

### 镜头 4 ｜ 0:55 – 1:15 ｜ bus factor：真正的价值

**画面**

| 秒 | 动作 |
|---|---|
| 0:55 | 画面**左右分屏**：左边活跃仓库结果页的 bus factor，右边死仓库的（提前开好两个标签页，或剪一次此处允许的硬切） |
| 0:58 | 鼠标在两块之间来回点两次，强调对比 |
| 1:02 | 放大 / 高亮死仓库文档里的那一句：**「这个人离开，项目即终止」** |
| 1:08 | 右上角浮出一行小字：`bus factor = 1 → 该维度 0 / 25 分` |
| 1:12 | 回到单页，指向「四、教训」 |

**旁白（中文）**

> 这才是它真正想告诉你的事。
> 左边这个项目，十几个人在提交，走一个不影响。
> 右边这个，**一个人占了六成以上的提交**。
> 这就是 bus factor 等于一——**这个人离开，项目即终止**。
> 这一项直接扣掉二十五分。
> 你不需要等到他离职那天才知道这件事。

**旁白（English subtitle）**

> This is what it's actually for.
> Left: a dozen contributors. Lose one, nothing happens.
> Right: **one person holds over sixty percent of all commits.**
> That's a bus factor of one — **if this person leaves, the project ends.**
> It costs twenty-five points on its own.
> You don't have to wait for their resignation letter to find out.

**要点**：这 20 秒是实用分（25%）的唯一落点。语速放慢，"六十 percent"和"二十五分"两个数字咬清楚。

### 镜头 5 ｜ 1:15 – 1:30 ｜ 收尾

**画面**

| 秒 | 动作 |
|---|---|
| 1:15 | 切到 README 顶部（项目名 + 徽章区 + ASCII 流程图） |
| 1:19 | 快速下滚过技术栈表（1.5 秒带过，不停留） |
| 1:22 | 出现大字：`打分是确定的，叙事是 AI 写的。` |
| 1:24 | 第二行：`分析层零 AI · 同一仓库两次跑分数完全相同` |
| 1:26 | 最后一张字幕卡：`[HF_SPACE_URL]` + `github.com/cslkkl/code-requiem` |
| 1:28 | 静帧 2 秒 |

**旁白（中文）**

> 打分全部是确定性算法，AI 只负责把它写成人话。
> 分析层里没有一行 AI，同一个仓库跑两次，分数一模一样。
> 给还活着的项目写遗嘱，给已经死掉的项目写悼词。
> 地址在屏幕上。

**旁白（English subtitle）**

> The score is deterministic. The AI only writes the prose.
> No AI in the analysis layer — same repo, twice, identical score.
> A will for the living. A eulogy for the dead.
> Link on screen.

## 3. 演示用仓库与预期分数区间

| # | 用途 | 仓库地址 | 预期分数 | 预期模式 |
|---|---|---|---:|---|
| 1 | 活跃大型库 | `https://github.com/kornia/kornia` | **75 – 90** | 代码遗嘱 |
| 2 | 单人维护小项目 | `https://github.com/cslkkl/dsh-cpa-switch` | **30 – 69** | 临终关怀（含 bus factor = 1） |
| 3 | 已归档 / 长期无提交 | `https://github.com/facebookarchive/caffe2` | **0 – 15** | 项目悼词 |

**备选（主选跑不出预期区间时替换）**

| 用途 | 备选仓库 | 预期分数 | 备注 |
|---|---|---:|---|
| 活跃库 | `https://github.com/psf/requests` | 70 – 85 | 老牌库，issue 量大，响应中位数可能拖分 |
| 死仓库 | `https://github.com/twbs/bootstrap-sass` | 5 – 20 | 已归档，最后提交久远 |
| 死仓库 | `https://github.com/kennethreitz/records` | 5 – 20 | 极小项目，bus factor 必然 = 1 |

**区间来自** [`docs/SPEC.md` 第 3.8 节](SPEC.md) 的参考分布。**实测偏离时的处理顺序：**

1. 先确认网络正常（依赖 API 超时会走中性 8 分，把总分拉高约 3–7 分）
2. 再确认不是 GitHub API 限速（未认证 60 次/小时，issue 维度会掉到 1 分）
3. 都正常还偏离 → **改口播稿里的数字，不改实现**。视频说真话才有说服力。

> 镜头 2 要"活着"，镜头 3 要"死了"，两者分数差距越大，画面冲击越强。
> 如果主选的第 3 个仓库分数不够低，优先换成归档更久、贡献者更少的仓库。

## 4. 录制建议

### 软件与参数

| 项 | 建议值 | 说明 |
|---|---|---|
| 录制软件 | **OBS Studio**（显示器采集或窗口采集） | 免费、稳、能直接录 1080p60 |
| 画布 / 输出分辨率 | **1920×1080** | 评审在浏览器里看，16:9 最安全 |
| 帧率 | 30 fps（够用）或 60 fps（滚动更顺） | 60 fps 文件更大，30 fps 足够 |
| 码率 | 6000–8000 Kbps，H.264 | 低于 4000 文字会糊，看不清分数 |
| 区域 | **窗口采集浏览器窗口**，不要全屏录桌面 | 全屏会带上任务栏和无关图标 |
| 音频 | 不录旁白音频，只烧字幕 | 90 秒里口音/环境噪音是纯风险；字幕更可控 |

### 画面

- 浏览器缩放到 **110%–125%**，确保 1080p 下分数数字和文档正文都可读
- 光标移动**慢**、**有目的**，不要无意义画圈；每次点击前停 0.5 秒
- **不要加速等待过程**。转圈那 4 秒是"它真的在分析"的证据，加速反而像造假
- 暗色主题优先（Streamlit 可配），分数色块对比更强

### 字幕

- **中英双语，全部烧进画面**，不依赖 B 站 / YouTube 的 CC
- 中文第一行，字号约 44–52px（1080p 下）；英文第二行，字号约 30–34px，颜色 70% 灰
- 底部留安全边距 ≥ 80px，避免被播放器控件遮住
- 一句话不超过 **18 个汉字**，超过就断成两条字幕
- 用 `[HF_SPACE_URL]` 那一帧**至少停留 2 秒**，够观众截图

### 剪辑

- 全程**只允许两处硬切**：镜头 1→2（进界面）、镜头 3→4（分屏对比）
- 分析过程中的等待**不允许剪**（这是实现分 30% 的核心证据）
- 不加背景音乐，或音量压到 -30dB 以下；音乐盖住信息是减分
- 导出 MP4（H.264 + AAC），文件名 `code-requiem-demo-90s.mp4`

### 上传

- 首选 YouTube（unlisted 也可）或 B 站，链接填进 Devpost 第 ⑤ 项
- 标题：`Code Requiem — 90 seconds from repo URL to handover document`
- 简介第一行写清楚：`Live demo: [HF_SPACE_URL]` / `Source: https://github.com/cslkkl/code-requiem`

## 6. 录完自检

- [ ] 时长在 60–90 秒之间（不是 91 秒）
- [ ] 两段分析过程**连续可见**，没有剪掉等待
- [ ] 活跃仓库分数 ≥ 70，死仓库分数 < 30（画面上的数字与口播一致）
- [ ] bus factor 那 20 秒里，两个项目的对比一眼能看懂
- [ ] 中英字幕都在画面里，没有超出底部安全区
- [ ] 最后 2 秒能看到 `[HF_SPACE_URL]`（已替换成真实地址）
- [ ] 全片没有出现任何 token、密码、个人邮箱、其他标签页
- [ ] 导出文件能在另一个设备上正常播放（别只在录制机上验证）
